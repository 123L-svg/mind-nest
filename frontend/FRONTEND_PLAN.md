# 前端建设方案（V1 保留增强）

> 范围：MindNest（智巢）· AI 笔记与知识库系统 · 前端（Vue3 + Vite + Element Plus + Pinia）
> 目标：在不换技术栈、不中断后端联调的前提下，完成 **UI 视觉升级 + 代码工程化重构 + 体验与功能补全**。
> 原则：渐进式改造、每阶段可独立验收、可随时回退；深色模式与设计令牌先落地，重构分块推进。

---

## 一、现状盘点（基线）

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| 技术栈 | Vue3（`<script setup>`）+ Vite5 + Element Plus + Pinia + axios + ECharts + WangEditor | 保留，仅做增强 |
| 页面 | Dashboard / NoteEdit / Login / Profile / Recycle / Stats / Tag / Category / Share / OAuthCallback（10 个） | 功能完整，结构需梳理 |
| 基建 | `api/http.js`+`api/index.js`、`router/index.js`(+守卫)、`store/user.js`、`main.js` 注入 `window.$message` | 可用，工程化不足 |
| 短板 | 组件化低（仅 `UserBadge`）；无 services/utils/hooks/constants 分层；样式多内联/scoped、无主题变量、无深色模式；无骨架屏/乐观更新/移动端适配；路由懒加载已用但未按"需拆"验证 | 逐一补齐 |

---

## 二、总体目标

1. **可用里**：构建/启动/联调不回归，`npm run build` 通过、Vite dev 可用。
2. **可维护**：目录分层清晰、可复用组件抽取、统一请求层与错误处理、常量/工具收敛。
3. **可感知**：统一设计语言（主题变量 + 深色模式）、友好空态/错误态/加载态、基础移动端适配。

---

## 三、目录与工程化目标结构

改造后推荐结构（渐进迁移，不追求一步到位）：

```
frontend/src/
├── main.js / App.vue
├── styles/              # 设计令牌与全局样式（新增）
│   ├── tokens.css        # 色彩/间距/圆角/阴影 CSS 变量（明暗双套）
│   ├── index.css         # 全局 reset + 基础类
│   └── dark.css          # 深色模式变量覆盖
├── api/                 # 请求层（沿用 axios 封装，增强）
│   ├── http.js           # 拦截器（注入 token、401 处理、统一错误）
│   └── index.js          # 各模块 api（保持现状，补 JSDoc/类型注释）
├── router/index.js      # 路由 + 守卫（保持）
├── store/               # Pinia
├── composables/         # 组合式函数（新增，酌情）
├── constants/           # 常量收敛
├── utils/               # 纯函数工具
├── components/          # 通用组件抽取
│   ├── UserBadge.vue
│   ├── AppEmpty.vue / AppError.vue / AppLoading.vue   # 状态组件（新增）
│   └── ...
└── views/               # 页面（保持，内部按需抽取）
```

> TS 说明：V1 阶段不强改 TS，仅对 `http.js`/`api` 增加 JSDoc 类型注释；如需可后续单独升级。
